# Публикация платформы «Контейнерный Союз» — пошагово, без вложений

Инструкция для прохождения этапа публикации «рука в руке». Каждый шаг — с проверкой результата: пока проверка не пройдена, к следующему шагу не переходим.

**Что понадобится:** почта, браузер и ~40 минут. Деньги — не нужны ни на одном шаге.

**Что получится в конце:** сайт вида `https://<логин>.github.io/container-union/` с общей базой данных, где регистрации перевозчиков, заявки, ставки и голосования Совета видны всем участникам, а не только в вашем браузере.

---

## Схема публикации

```
Шаг 1  Проверка файлов локально            → платформа открывается, всё считается
Шаг 2  Аккаунт GitHub и репозиторий        → файлы в облаке, есть история версий
Шаг 3  Включение GitHub Pages              → сайт доступен по публичной ссылке
Шаг 4  Проект в Supabase (база)            → база создана, таблицы на месте
Шаг 5  Вставка ключей в config.js          → платформа онлайн: «база: Supabase · онлайн»
Шаг 6  Сквозная проверка                   → регистрация/заявка/голосование видны в базе
Шаг 7  Режим работы и обновления           → как править сайт и документы онлайн
```

---

## Шаг 1. Проверка файлов локально

1. Скачайте из рабочей папки 4 файла (остальные — справочные):

| Файл | Обязателен |
|---|---|
| `index.html` | да |
| `config.js` | да |
| `Документы_Контейнерный_Союз.md` | да (тексты документов) |
| `README.md` | по желанию |

2. Откройте `index.html` двойным щелчком.

**Проверка пройдена, если:**
- в шапке виден логотип **КС**, при наведении он разворачивается в «Контейнерный Союз»;
- открывается вкладка «О платформе» с блоком «Переходный период» и счётчиком `0 / 50`;
- в калькуляторе кнопка «Рассчитать ставку» выдаёт сумму (например, Новороссийск → Москва, 40′HC — около 184 000 ₽);
- в правом верхнем углу: «хранилище: локальный демо-режим» — это нормально, база подключится на шаге 5.

---

## Шаг 2. Аккаунт GitHub и репозиторий

1. Откройте **github.com** → **Sign up** (или войдите). Логин лучше выбрать нейтральный: например, `konsouz` или `container-union`. Он попадёт в адрес сайта, поэтому без случайных слов.
2. **+** (вверху справа) → **New repository**.
3. Заполните:
   - **Repository name:** `container-union`
   - **Description:** Открытая платформа контейнерных автоперевозок России
   - **Public** (обязательно: с приватного репозитория бесплатный Pages не работает)
   - **Add a README file** — можно поставить галочку, файл перезапишем своим.
4. **Create repository**.
5. На странице репозитория: **Add file → Upload files**. Перетащите `index.html`, `config.js`, `Документы_Контейнерный_Союз.md`, `README.md`. Внизу: **Commit changes**.
   - Если русские имена файлов вызывают неудобства, переименуйте документ в `docs/Documents.md` — на работу платформы это не влияет.

**Проверка пройдена, если:** в репозитории видно 4 файла, у `index.html` в списке отображается размер и время коммита.

---

## Шаг 3. Включение GitHub Pages

1. В репозитории: **Settings** → в левом меню **Pages**.
2. **Source:** `Deploy from a branch` → **Branch:** `main`, папка `/ (root)` → **Save**.
3. Подождите 1–3 минуты, обновите страницу: сверху появится адрес вида `https://konsouz.github.io/container-union/`.
4. Откройте адрес в браузере.

**Проверка пройдена, если:** сайт открылся, логотип разворачивается, калькулятор считает.
Если через 5 минут пишет «404» — проверьте, что выбран именно `main` и папка `/ (root)`, и что `index.html` лежит в корне репозитория, а не в подпапке.

На этом шаге сайт уже публичный. Дальше подключаем общую базу.

---

## Шаг 4. Проект в Supabase (бесплатная база)

1. Откройте **supabase.com** → **Start your project** → войдите через GitHub (так проще).
2. **New project**:
   - Name: `container-union`
   - Database Password: придумайте и **сохраните** (например, в заметках) — он понадобится только для прямого доступа к базе.
   - Region: `Frankfurt (eu-central-1)` — ближайший к РФ из доступных.
   - Plan: **Free**.
3. Подождите 1–2 минуты, пока проект создаётся.
4. **SQL Editor** → **New query**.
5. Откройте файл `supabase/schema.sql` (лежит в рабочей папке), скопируйте **весь** текст, вставьте в окно, нажмите **Run**.
6. Ожидаемый результат: `Success. No rows returned`.
7. Проверьте: **Table Editor** → слева должен быть список таблиц `tariff`, `carriers`, `applications`, `loads`, `bids`, `votes`, `vote_ballots`, `decisions`, `journal`, `settings`. В `tariff` — одна строка с тарифной сеткой, в `settings` — строка `council` с порогом выборов 50.

**Проверка пройдена, если:** таблицы созданы, в `tariff` есть строка с `fuelPrice = 86.72`.

## Шаг 5. Ключи в `config.js` и включение онлайн-режима

1. В Supabase: **Settings → API**.
2. Скопируйте два значения:
   - **Project URL** — вида `https://xxxxxxx.supabase.co`;
   - **anon public** — длинный ключ (это публичный ключ, он специально предназначен для клиентского кода).
3. В GitHub откройте `config.js` → значок карандаша (Edit) → вставьте значения:

```js
window.KONTREIT_CONFIG = {
  supabaseUrl: 'https://xxxxxxx.supabase.co',
  supabaseAnonKey: 'eyJhbGciOiJIUzI1NiIsInR5cCI6...',
  mode: 'auto'
};
```

4. **Commit changes** → подождите минуту, обновите сайт.

> **Никогда** не вставляйте в `config.js` ключ `service_role` (в разделе API он тоже есть). Этот ключ обходит все правила доступа и должен использоваться только на сервере.

**Проверка пройдена, если:** в правом верхнем углу сайта написано **«база: Supabase · онлайн»** (изначально может быть «база: подключение…» — обновите страницу через 30 секунд).

## Шаг 6. Сквозная проверка связки

Пройдите по шагам и каждый раз сверяйтесь с базой (Supabase → Table Editor → нужная таблица).

| Действие на сайте | Что должно появиться в базе |
|---|---|
| Кабинет → форма регистрации перевозчика → «Отправить заявку» | `carriers` — новая строка (`demo = false`), `applications` — заявка на верификацию |
| Грузы → «Разместить заявку» | `loads` — новая строка с полями `from_city`, `to_city`, `pickup` |
| Реестр перевозчиков → карточка → «Подать ставку» (режим «Перевозчик») | `bids` — строка со ставкой; в `loads` у заявки обновился счётчик |
| Совет перевозчиков → «Внести предложение» | `votes` — новый вопрос |
| Кабинет администратора → «Верифицировать» заявку | `carriers.status = verified`; счётчик на вкладке Совета вырос (шаг к 50) |
| Кнопка «⟳ Обновить данные из базы» | свежие данные всех участников подтянулись |

**Проверка пройдена, если:** после каждого действия в базе появляется соответствующая строка. Если строк нет — пришлите текст ошибки из консоли браузера (F12 → Console), он начинается с `[Контейнерный Союз/Supabase]`.

### Готовые отчёты в базе (SQL Editor)

```sql
select count(*) from carriers where status = 'verified' and coalesce(demo, false) = false;
-- ↑ готовность к выборам Совета: порог 50

select * from v_registry order by fleet desc;            -- реестр перевозчиков
select * from v_route_stats order by loads_total desc;   -- плечи: рейсы и средние ставки
select * from v_vote_results order by deadline desc;     -- итоги голосований с порогами
select * from journal order by created_at desc limit 50; -- журнал платформы
```

## Шаг 7. Рабочий режим и обновления онлайн

**Как править сайт.** В GitHub: откройте файл → карандаш → правите → **Commit changes**. Через 1–2 минуты изменения на сайте. История версий сохраняется автоматически — любую правку можно откатить.

**Как править документы.** `Документы_Контейнерный_Союз.md` — обычный текст в формате Markdown. Правьте формулировки прямо на GitHub (кнопка «Preview» показывает, как будет выглядеть). Каждое изменение — коммит с комментарием вроде «Устав, ст. 11: изменить кворум Совета». Так формируется протокол изменений: кто, когда и что поменял.

**Как менять тарифную сетку.** Два пути:
- через платформу: Совет перевозчиков → «Внести предложение» → (Администрация) «Утвердить в переходный период» — тариф обновится и на сайте, и в базе;
- напрямую в базе: Supabase → Table Editor → `tariff` → отредактировать строку → на сайте нажать «⟳ Обновить данные из базы».

**Ежедневный ритуал (2 минуты):**
1. открыть `https://<логин>.github.io/container-union/` — проверить, что сайт жив;
2. Supabase → Table Editor → `applications` — посмотреть новые заявки;
3. Supabase → `carriers` — посмотреть, сколько верифицированных набралось (цель — 50).

**Раз в 3–4 дня** открывайте проект в консоли Supabase: бесплатные проекты засыпают после ~7 дней без активности. Как альтернатива — бесплатный ping через GitHub Actions (cron раз в 2 дня на адрес `${SUPABASE_URL}/rest/v1/tariff?select=id`, ключ `anon`).

**Раз в неделю** выгружайте резервную копию: Supabase → Table Editor → нужная таблица → Export → CSV. Складывайте в тот же репозиторий или в облачный диск.

## Когда наберётся 50 перевозчиков

Порог достигнут → на вкладке «Совет перевозчиков» активируется кнопка **«Назначить выборы Совета»**:

1. нажатие фиксирует даты: выдвижение кандидатов — 20 дней, голосование участников — 15 дней;
2. по итогам голосования Администрация публикует избранный состав (9 мест), переходный период завершается;
3. с этого момента тарифные решения принимаются только голосованием Совета: 6 из 9 (тарифы), 5 из 9 (работа платформы), 7 из 9 (Устав), кворум — 7 членов.

До этого момента платформа остаётся полностью рабочей: калькулятор, реестр, рейтинг, биржа и открытые обсуждения — действуют.

## Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| «база: нет связи (локальный режим)» | проверьте `config.js`: адрес должен начинаться с `https://` и заканчиваться на `.supabase.co`, ключ — длинная строка. Обновите страницу |
| Записи не появляются в базе | проверьте, что выполнили `schema.sql` целиком и в настройках RLS включены политики `proto_all` (Supabase → Authentication → Policies) |
| «404» на адресе Pages | в Settings → Pages должен быть выбран `main` и `/ (root)`; файл `index.html` — в корне репозитория |
| Русские файлы отображаются кракозябрами | это редкость на GitHub; при проблемах переименуйте документ латиницей (`docs/Documents.md`) — сайт от этого не пострадает |
| Сайт открылся, но логотип не разворачивается | обновите страницу с очисткой кэша (Ctrl+F5) |
| Нужно стереть демонстрационные профили из базы | в SQL Editor: `delete from carriers where demo;` |

## Что дальше после публикации

1. **Наполнение реестра:** пригласите 10–15 перевозчиков по одному-двум плечам (например, Новороссийск → Москва и Новороссийск → Екатеринбург), помогите им пройти регистрацию и верификацию.
2. **Первые реальные заявки:** 2–3 грузовладельца или экспедитора — их заявки дадут рейтингу и полам Совета живые данные.
3. **Публичный отчёт:** раз в месяц — короткая заметка «Как менялась ставка на плече X и почему» на основе `v_route_stats`. Это и есть смысл платформы: цена, объяснённая расчётом.
4. **Юридический этап:** когда в реестре будет устойчивое ядро, зарегистрировать объединение (ассоциация/АНО) и провести первые выборы Совета уже как органа юридического лица.

Пришлите, на каком шаге вы находитесь, — подскажу точные действия для следующего, включая разбор ошибок из консоли браузера.
