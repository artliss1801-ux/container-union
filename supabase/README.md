# Как включить живую базу «Контейнерного Союза» за 10 минут (бесплатно)

После этих шагов регистрации перевозчиков, заявки, ставки и голосования Совета перестанут «жить в браузере» и станут общими для всех участников.

---

## Шаг 1. Проект в Supabase

1. Откройте **supabase.com** → **Start your project** → регистрация через GitHub или e-mail.
2. **New project**: name — `container-union`, database password — сохраните в надёжном месте, Region — ближайший доступный (для России обычно Frankfurt / `eu-central-1` или Stockholm).
3. Подождите 1–2 минуты, пока проект поднимется.

## Шаг 2. Создание таблиц

1. В проекте: **SQL Editor** → **New query**.
2. Откройте файл `supabase/schema.sql` из этого репозитория, скопируйте **весь** текст и вставьте в окно.
3. Нажмите **Run** (Ctrl+Enter). Должно появиться `Success. No rows returned`.
4. Проверка: **Table Editor** → таблицы `tariff` (одна строка с тарифной сеткой), `settings` (строка `council` с порогом выборов 50), `carriers`, `loads`, `votes`. Таблица `council_members` **пуста** — это правильно: Совет перевозчиков появится после выборов.

## Шаг 3. Ключи доступа

1. **Settings → API** (Project Settings → API).
2. Скопируйте:
   - **Project URL** — вида `https://abcdefgh.supabase.co`;
   - **anon public** — длинный ключ (безопасно публиковать в клиентском коде).
3. Вставьте оба значения в файл `config.js`:

```js
window.KONTREIT_CONFIG = {
  supabaseUrl: 'https://abcdefgh.supabase.co',
  supabaseAnonKey: 'eyJhbGciOi...',
  mode: 'auto'
};
```

> **Никогда** не вставляйте в `config.js` ключ `service_role` — он даёт полный доступ к базе и должен оставаться только на сервере.

## Шаг 4. Публикация сайта

Загрузите в репозиторий (GitHub) файлы:

```
index.html                        ← сама платформа
config.js                         ← ключи базы
Документы_Контейнерный_Союз.md    ← тексты документов
Публикация.md                     ← инструкция (по желанию)
supabase/schema.sql               ← схема базы (по желанию, для истории)
```

Включите **Settings → Pages** → Source: `main`, папка `/root`. Сайт будет доступен по адресу `https://<ваш-логин>.github.io/<репозиторий>/`.

Так же работает бесплатно: **Cloudflare Pages** (drag & drop папки) или **Netlify Drop**.

## Шаг 5. Проверка

1. Откройте опубликованный сайт: в правом верхнем углу должно быть **«база: Supabase · онлайн»**.
2. Вкладка «Кабинет» → заполните форму регистрации → отправьте.
3. В Supabase: **Table Editor → carriers** и **applications** — записи появились.
4. Вкладка «Грузы» → «Разместить заявку» → заявка появится в таблице `loads`.
5. Вкладка «Совет перевозчиков» → «Внести предложение» → в таблице `votes` появится вопрос. Включите «Учебный режим» и проголосуйте — в `vote_ballots` появится бюллетень, а в `v_vote_results` — итоги с порогами.
6. Кабинет администратора → «Верифицировать» заявку → в таблице `carriers.status = verified`, а счётчик на вкладке Совета вырос (шаг к порогу 50 перевозчиков и выборам).
7. Кнопка **«⟳ Обновить данные из базы»** подтягивает свежие данные у всех участников.

## Шаг 6. Что смотреть в базе (готовые отчёты)

В SQL Editor:

```sql
select * from v_vote_results order by deadline desc;    -- итоги голосований с порогами
select * from v_registry order by fleet desc;           -- реестр перевозчиков
select * from v_route_stats order by loads_total desc;  -- экономика плеч: рейсы и средние ставки
select * from tariff_log order by created_at desc;      -- история тарифной сетки
select * from journal order by created_at desc limit 50;-- журнал действий платформы
```

## Шаг 7. Перед реальным запуском (обязательно)

1. Включите **Authentication** (Email или Phone) и создайте пользователей для Администрации, членов Совета и перевозчиков.
2. Примените **STRICT-РЕЖИМ** — блок 9 в конце `supabase/schema.sql`: чтение открытых данных всем, запись — только владельцу карточки / авторизованному участнику / члену Совета.
3. Заведите отдельного пользователя для Администрации платформы; служебные операции — через серверную функцию (Edge Function) с ключом `service_role`.
4. Включите ежедневные резервные копии (на бесплатном тарифе — 7 дней истории; раз в неделю делайте выгрузку таблиц в CSV через Table Editor).
5. Настройте «keep-alive»: бесплатные проекты Supabase приостанавливаются после ~7 дней без активности. Достаточно раз в 3–4 дня открывать проект в консоли либо настроить бесплатный ping через GitHub Actions (cron раз в 2 дня) на адрес `${SUPABASE_URL}/rest/v1/tariff?select=id`.

## Если Supabase недоступен

Альтернативы с тем же принципом (общая база + доступ по ключу):

- **Google Таблица + Apps Script** — таблица как база, скрипт как REST-API (`doGet` / `doPost`). Плюс: работает без VPN, всё видно глазами. Минус: медленнее и слабее по правам доступа.
- **Yandex Cloud** (Object Storage + Cloud Functions) — бесплатный лимит на запросы и хранение; потребует чуть больше настройки.
- **Собственный сервер**: Node.js + PostgreSQL на любом VPS (не бесплатно, от ~200 ₽/мес).

Платформа не привязана к конкретному бэкенду: интерфейс обращается к базе через один слой запросов (`parts/p5.online.js`), поэтому подмена бэкенда — это правка одного файла.
