  mkdir -p /tmp/smoke && cd /tmp/smoke && cp /home/user/tests/*.js . && npm i jsdom

ЛОКАЛЬНЫЕ НАБОРЫ (без сети, эмулятор базы внутри теста)
  node test_master.js     — прототип целиком (19 проверок): вкладки и роли в демо-режиме, переходный период,
                            выборы; параметры сетки и рыночный ориентир меняются ТОЛЬКО решением (проект →
                            утверждение Администрацией, после выборов — голосование Совета); учебный режим
                            не меняет сетку; курсы подтягиваются из открытого источника (ЦБ РФ), открытые
                            данные ночного сбора переносятся в проект решения; база НП России и автоподбор;
                            дополнительные точки (таможня) в ставке; регистрация; калькулятор
  node test_strict.js     — роли и защита админ-действий против эмулятора Supabase (28 проверок):
                            регистрация создаёт аккаунт и роль carrier автоматически, карточка привязывается
                            к аккаунту, перевозчик не верифицирует себя, не поднимает себе роль, не видит
                            заявки; администратор назначает роли и снимает доступ; главного администратора
                            нельзя понизить или удалить; участник без роли управления не видит
  node test_design.js     — интерфейс: единственный логотип в шапке и разворот по буквам, меню разделов
                            слева (открытие, Esc, ✕, блокировка прокрутки), стабильная шапка без тряски,
                            лента событий, пресеты и авторасчёт калькулятора, поиск, клавиши ← → (17 проверок)

ЖИВЫЕ НАБОРЫ (проверяют ОПУБЛИКОВАННЫЙ сайт и настоящую базу Supabase)
  node live_roles.js      — полный цикл ролей (18 проверок): гость видит только вход и регистрацию;
                            регистрация перевозчика → роль присвоена базой → карточка pending с владельцем;
                            перевозчик не может верифицировать себя и стать администратором, заявки ему
                            не видны; вход администратора; раздел «Пользователи и роли»; назначение
                            «член Совета» и «администратор»; 403 на понижение главного администратора;
                            снятие доступа. В конце убирает тестовые записи и аккаунт.
                            Секреты — только через переменные окружения:
      SUPABASE_MGMT_TOKEN=… ADMIN_EMAIL=… ADMIN_PASSWORD=… node live_roles.js
  node live_public.js     — публичный осмотр (10 проверок): сайт на живой базе, «режима просмотра» нет
                            ни в интерфейсе, ни в текстах, в шапке только вход и регистрация, кабинет гостя —
                            форма заявки с e-mail и паролем, калькулятор на живом тарифе, реестр,
                            строка показателей, меню по кнопке, гость не может верифицировать перевозчика,
                            0 ошибок JS
  node live_indicators.js — строка показателей на живом сайте (12 проверок): статичная и без событий,
                            ДТ/«Платон»/ориентир и блок тарифной сетки совпадают с базой, курс USD взят из базы
                            с источником и датой, Администрация меняет ориентир (в переходный период —
                            с записью в реестр решений) и курсы, открытые данные ночного сбора видны
                            и переносятся в проект решения, гость записать не может. После проверки значения
                            возвращаются к исходным (тариф, настройки, тестовые записи удаляются).
                            Запуск: SUPABASE_MGMT_TOKEN=… ADMIN_EMAIL=… ADMIN_PASSWORD=… node live_indicators.js
  node live_admin_write.js — записи администратора в закрытую базу: тариф и настройки Совета сохраняются,
                            значения не портятся (5 проверок). Логин/пароль — через ADMIN_EMAIL / ADMIN_PASSWORD
  node live_design.js     — дизайн на живом сайте: логотип и его разворот, строка показателей с данными базы,
                            пресеты на живой сетке, стабильная шапка (6 проверок)

ПОКАЗАТЕЛИ И ОТКРЫТЫЕ ИСТОЧНИКИ
  Курсы валют на сайте подтягиваются из ЦБ РФ (зеркало cbr-xml-daily.ru, CORS открыт). ДТ и «Платон»
  собирает ночная задача GitHub — скрипт tools/fetch_indicators.mjs (запись в settings, ключ indicators).
  Проверить сбор без записи в базу: node tools/fetch_indicators.mjs --dry
  База НП России: tools/build_settlements.py (аргумент — путь к city.csv набора hflabs/city).

Примечания
  * В онлайн-наборах учёт администратора и служебный токен передаются ТОЛЬКО переменными окружения —
    в файлах репозитория секретов нет (GitHub блокирует пуш с ними).
  * После записи в базу тестам нужна пауза (~1,2–1,5 с): записи идут асинхронно.
  * Наборы live_auth.js и live_final.js удалены — они проверяли прежнюю модель с «режимом просмотра»;
    их проверки вошли в live_roles.js и live_public.js.
